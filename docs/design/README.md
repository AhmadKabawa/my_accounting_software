## حالة المواصفات (مراجعة 2026-11-26)
الحالة من قراءة الكود على الفرع `feat/cat07-categories-ui`؛ **لم تُشغَّل اختبارات Flutter ولم يُفحص Supabase الحي أو CI لآخر commit**. «منفذة» تعني وجود الكود، لا اعتماد المالك البصري.

| المواصفة | الحالة | المتبقي الأهم |
|---|---|---|
| CAT-07 الماركات | منفذة (القالب المرجعي) | B-01 رفع الشعار، التحقق الحي |
| CAT-07 الألوان | منفذة | اعتماد CL-1..CL-6، B-20..B-24 |
| CAT-07 التصنيفات | منفذة | G-1 «إضافة فرعي» من الصف، D-CAT-5، B-25 |
| CAT-07 أنواع المنتجات | غير منفذة (التالية) | المرحلة أ ثم ب بلا `Tabs` |
| CAT-07 الوحدات | غير منفذة | قبل الخصائص |
| CAT-07 الجداول الوصفية | غير منفذة | `genders` أولاً، `DatePicker` في Core للمواسم والمجموعات |
| CAT-07 أنظمة المقاسات | غير منفذة | تعتمد على `genders` |
| CAT-07 الخصائص والخيارات | غير منفذة | تعتمد على الوحدات |
| CAT-01 قائمة المنتجات | غير منفذة | بعد أنواع المنتجات وCAT-02 |

ترتيب التنفيذ المقترح: أنواع المنتجات (أ) ← الوحدات ← `genders` ← أنظمة المقاسات ← الخيارات والخصائص ← بقية الجداول الوصفية ← CAT-02 ← CAT-01 ← أنواع المنتجات (ب).

## دورة العمل
تحليل ← متطلبات ← مواصفة ← قرارات مفتوحة ← تنفيذ ← تحقق.

لا يبدأ التنفيذ قبل مراجعة المواصفة واعتمادها. أي قرار غير مدعوم بمصدر يُسجل بوضوح كاقتراح أو قرار مفتوح، ولا يتحول إلى وظيفة ضمنية.
