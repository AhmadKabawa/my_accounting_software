## 0. الملخص

قائمة مرقّمة خادمياً للمنتجات (الموديلات، لا المتغيرات) بالبحث والفلاتر (النوع، الماركة، الحالة) وصف بهوية بصرية (صورة أساسية، الاسم، رمز الموديل)، تفتح CAT-02 بالنقر. **القائمة للوصول والعثور فقط**: إنشاء المنتج وتعبئته ونشره وأرشفته كلها في CAT-02 (S07 وS54)؛ وجود المنتج `draft` أو `published` أو `archived` يُعرض هنا ولا يُغيَّر هنا. القراءة مفتوحة بـ RLS، والكتابة `catalog.manage`.

## 1. معلومات الشاشة
- **الوحدة:** الكتالوج ← المنتجات. **النوع:** قائمة (قالب T1).
- **لماذا وحدة مفهومة؟** نقطة الدخول الوحيدة إلى المنتج؛ كل شاشات الكتالوج الأخرى (التسعير، التكلفة، الملصقات) تبدأ من منتج تختاره منها (خريطة التنقل §7).

## 2. الهدف والنتيجة
- **المشكلة:** أمين المستودع أو المشتري يريد العثور على موديل بالاسم أو الرمز أو الباركود بسرعة، ومعرفة حالته وماركته ونوعه.
- **النتيجة:** يجد المنتج في أقل خطوات، يفتحه، أو يبدأ «منتج جديد».
- **اكتمال المهمة:** S07 §10: «لا منتجات» مع زر الإنشاء للمخوَّل؛ والنتائج تتفق مع البحث والفلاتر.
- **لماذا لا قائمة متغيرات؟** المتغيرات (لون × مقاس) تُدار في CAT-02؛ القائمة بمستوى الموديل أوضح وأقل كلفة.

## 4. المستخدمون والصلاحيات
- **الكتابة (زر «منتج جديد»):** `catalog.manage` → MANAGER وPURCHASER وWAREHOUSE وSUPER_ADMIN.
- **القراءة:** مفتوحة وفق RLS؛ **AUDITOR** «اطلاع» في خريطة التنقل، ولا يملك `catalog.manage`. المصدر نفسه يربط بند القائمة بـ `catalog.manage` → **تعارض (D-01-2)**.
- **واجهة القراءة:** لا تُحجب القائمة عن مستخدم read-only (نمط الماركات)؛ يُخفى «منتج جديد» عنه.
- **403 على GET:** حالة Permission Denied مستقلة.
- **المرجع النهائي:** RLS؛ `PermissionGate` تحسين عرض.

## 6. البيانات
| البيانات | الجدول | الحقول | العلاقة/FK | RLS |
|---|---|---|---|---|
| المنتج | `products` | `id`, `name`, `model_code`, `status`, `created_at` | — | قراءة `true` |
| الماركة | `brands` | `id`, `name` | `products.brand_id` (اختياري) | `true` |
| النوع | `product_types` | `id`, `name` | `products.product_type_id` (NOT NULL) | `true` |
| التصنيف الأساسي | `product_categories` → `categories` | `is_primary`, `categories.name` | `ux_pc_one_primary`: تصنيف أساسي **واحد** لكل منتج | `true` |
| عدد المتغيرات | `product_variants` | `count` | `product_id → products` | `true` |
| الصورة الأساسية | `product_images` | `image_url`, `is_primary` | `ux_pi_one_primary`: صورة أساسية واحدة لكل منتج | `true` |
| ألوان المنتج (اختياري، D-01-4) | `product_colors` → `product_color_components` → `colors` | `hex_code` | — | `true` |
- **ما يأتي من API:** كله. **ما يحسبه العميل:** لا شيء (الإجماليات من `Prefer: count=exact`).
- **كلفة الاستعلام:** صف المنتج + 4 تضمينات (ماركة، نوع، تصنيف أساسي، عدّ المتغيرات) + صورة أساسية؛ بحجم صفحة 25 مقبول. تضمين الألوان يضاعف العمق (3 مستويات) فيُؤجَّل لقرار.
- التصنيف: يُقيَّد التضمين بـ `is_primary=true`؛ منتج بلا تصنيف أساسي يعرض «—».

## 10. البحث والفلاتر والفرز
- **البحث:** `name` و`model_code`، و**الباركود** (خريطة التنقل §12.4). **الباركود يقع في جدول بعيد** (`barcodes.variant_id → product_variants → products`)، ولا يمكن خلطه مع شرط `name` بـ `OR` ببساطة في PostgREST دون تضمين داخلي؛ ولا RPC ولا View مسموحة الآن. **قرار D-01-1.**
- **طريقة المطابقة:** `ilike` مع escaping لـ `%` و`_`؛ debounce 300ms داخل Cubit، وآخر طلب يفوز.
- **الفلاتر (S07):** النوع (`SearchableDropdown` من `product_types` النشطة) · الماركة (من `brands` النشطة) · الحالة (الكل/مسودة/منشور/مؤرشف).
  - **لماذا هذه فقط؟** هي المنصوص عليها في S07 §6؛ التصنيف يحتاج دلالة «يشمل الأبناء» غير محسومة.
- **الفرز:** الاسم (افتراضي) و**تاريخ الإنشاء** (قرار معتمد، D-01-3). لا فرز بالباقي: لا حاجة موثقة.
- **عدد النتائج:** إجمالي المطابق بعد البحث والفلاتر.
- **التفاعل:** أي تغيير يعيد الصفحة 1؛ «مسح الكل» يعيد الافتراضي.
- **الحالة الافتراضية للفلتر:** «الكل» **(D-01-5)**.

## 11. القائمة
1. **الهوية:** صورة + الاسم + رمز الموديل (عمود أساسي).
2. **الحالة:** `AppBadge` بنص ولون (لا اللون وحده — ADR-0003 بند 9).
3. **الماركة.**
4. **النوع** و**التصنيف** (ثانويان).
5. **عدد المتغيرات.**
- **ترتيب الأعمدة:** هوية ← حالة ← ماركة ← نوع ← تصنيف ← متغيرات.
- **إجراء الصف:** النقر على الصف كله (لا زر تعديل منفصل لأن التعديل في CAT-02).
- **الترقيم:** 25 افتراضياً، 10/25/50/100.
- **الهاتف:** بطاقة (صورة، الاسم، الحالة، الماركة، عدد المتغيرات).
- **لا id ولا timestamps** (لا تخدم مهمة العثور).

## 14. التنقل
- **نقطة الدخول:** القائمة الجانبية (الكتالوج ← المنتجات).
- **الخروج:** CAT-02 بالنقر أو «منتج جديد».
- **العودة من CAT-02:** إلى القائمة **بالبحث والفلاتر والصفحة نفسها** (يُحفظ في حالة التنقل)؛ لماذا: المستخدم غالباً يراجع عدة منتجات متتالية.
- **الرابط العميق:** `/catalog/products` صالح دائماً؛ الفلاتر في query معلمات (قرار معتمد D-01-6).
- **breadcrumb:** «Catalog ← Products».

- النقاط أرقام اختبار لا breakpoints جديدة.

## 16. RTL/LTR
- اتجاه النص من لغة الواجهة. `model_code` وslug والباركود تُعرض LTR داخل RTL.
- الأسماء المختلطة (عربي + لاتيني) تُعرض بمحاذاة طبيعية بلا عكس يدوي.
- الأسهم والأيقونات الاتجاهية فقط تنعكس.

## 17. Light/Dark
- المتأثر: شارات الحالة والصور المصغرة والحدود والنصوص الثانوية.
- `context.ui.theme.colors` و`semanticColors` فقط؛ لا `Theme.of(context).colorScheme`.
- صورة المنتج بخلفية بيضاء على الوضع الداكن: حد `outlineVariant` حول المصغّرة (فحص يدوي).

## 18. Core ونظام التصميم
- المعاد استخدامه: كما في §9. `AppDensity` لا يُضبط صراحة (comfortable افتراضي، compact بسياق Core).
- المرجع: Ledger Design System وADR-0003.
- لماذا لا ننسخ Core؟ قاعدة ARCHITECTURE_RULES: لا بدائل موازية.

## 19. API
| العملية | Endpoint / Query | ملاحظات |
|---|---|---|
| GET | `/rest/v1/products?select=id,name,model_code,status,created_at,brands(id,name),product_types(id,name),product_categories(is_primary,categories(id,name)),product_variants(count),product_images(image_url,is_primary)&product_categories.is_primary=eq.true&product_images.is_primary=eq.true&order=name.asc` | `Range` للترقيم، `Prefer: count=exact` |
| فلتر النوع | `&product_type_id=eq.<id>` | |
| فلتر الماركة | `&brand_id=eq.<id>` | |
| فلتر الحالة | `&status=eq.<draft\|published\|archived>` | |
| بحث نصي | `&or=(name.ilike.*q*,model_code.ilike.*q*)` | الباركود: D-01-1 |
- **الأخطاء:** 401 جلسة · 403/42501 لا صلاحية · انقطاع · غير ذلك، عبر `ExceptionMapper → Failure.messageKey` (قرار-76).
- Retry: `GET` فقط (`RetryInterceptor`).
- **ما يُختبر بـ fake `IApiClient`:** بناء الاستعلام، التحويل (منتج بلا ماركة/تصنيف/صورة)، الترقيم، الأخطاء.
- **ما يحتاج تحققاً على الخدمة:** سلوك التضمين المقيَّد (`product_categories.is_primary=eq.true`) مع `left join`؛ `product_variants(count)`؛ أداء الصفحة بصور وتضمينات؛ مسار البحث بالباركود.
- **لماذا لا migration/RPC؟** كل البيانات قابلة للقراءة بالعلاقات المؤكدة؛ البحث بالباركود هو الاستثناء (D-01-1).

## 21. التنفيذ والاختبار
- **ترتيب التنفيذ:** Domain (Product, ProductListItem) ← Data (Model، endpoint، repository) ← UseCase ← Cubit (قائمة + debounce) ← Page رقيقة + widgets (الهوية، البطاقة، الفلاتر) ← Localization (ar/en + `key_registry`) ← DI في `catalog_di.dart`.
- **الاختبارات:** Model JSON (منتج بلا ماركة/صورة) · Repository (الاستعلام والفلاتر والترقيم والأخطاء) · Cubit (حالات، debounce، آخر طلب يفوز) · Widget 360/600/900/1200 × LTR/RTL × فاتح/داكن مع `tester.takeException()`.
- **المعمارية:** لا تُعطَّل `no_magic_numbers_test` و`no_raw_ui_in_features_test` و`feature_imports_test`.
- **التحقق الفعلي:** حساب `catalog.manage` وحساب read-only على Supabase؛ منتج بلا صورة؛ منتج بلا تصنيف أساسي.
- **التحقق البصري اليدوي:** Chrome عند 360 و1200، عربي/إنجليزي، فاتح/داكن — للمالك.
- **لم يُشغَّل:** `dart format` و`flutter analyze` و`flutter test` (لا Flutter SDK في بيئة إعداد المواصفة). لا نتائج مزعومة.
- **حدود التغطية:** لا تثبت جودة التباين ولا الترتيب البصري.
