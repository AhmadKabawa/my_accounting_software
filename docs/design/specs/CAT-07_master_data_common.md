## C2. الأدوار والصلاحيات

- **الكتابة:** `masterdata.manage` (MANAGER وPURCHASER وWAREHOUSE وSUPER_ADMIN) على كل جداول CAT-07.
- **القراءة:** مفتوحة (`read: true` في RLS لكل جداول CAT-07) حتى لمن لا يملك `masterdata.manage`.
- **واجهة القراءة:** لا تُحجب القائمة عن مستخدم القراءة فقط؛ أزرار الإنشاء والتعديل والإيقاف والحذف خلف `PermissionGate(masterdata.manage)`.
- **المرجع النهائي:** RLS في القاعدة؛ إخفاء الأزرار تحسين عرض فقط.
- **رفض القراءة (403):** حالة Permission Denied مستقلة، ليست Empty ولا خطأً عاماً.
- **تعارض موثّق (D-C2):** خريطة التنقل تضع AUDITOR «اطلاع» على CAT-07 وتربط بند القائمة بـ `masterdata.manage` التي لا يملكها AUDITOR (DATA_MODEL §6).

## C3. التنقل والمسارات

- كل شاشة صفحة مستقلة بمسار مستقل تحت `/catalog/...` (المسارات المقترحة في مواصفة كل كيان، وتُفحص مقابل `route_registry` و`app_go_router` قبل التنفيذ؛ أي تعارض يوقف التنفيذ ويُعرض).
- القرار D-01 في مواصفة الماركات: لا غلاف تبويبات ولا صفحة مركز «حتى تنفيذ التبويب الثاني». **هذه الشاشات تنقل المشروع إلى التبويب الثاني**، لذلك يلزم قرار D-C1 (القسم C11) **قبل** تنفيذ أي صفحة ثانية.
- breadcrumb: «Catalog ← [اسم الكيان]» دون تغيير توقيع `AppBreadcrumb`؛ يُضاف مستوى «البيانات الأساسية» عند اعتماد المركز فقط.
- لا عناصر قائمة جانبية جديدة ولا تبويبات وهمية لشاشة غير منفّذة.

## C4. القائمة: البحث والفلاتر والفرز والترقيم

القالب: `ListPageTemplate` + `FilterBar` + `AppDataTable` (الموجود في Core).

```
Breadcrumb: Catalog › <Entity>
Title (total count)                                [+ New]   <- PermissionGate
[ Search............ ] [ Status: All ▾ ] [ extra filter ▾ ] [ Clear ]
┌───────────────────────────────────────────────────────────────┐
│ identity cell │ secondary cols │ status badge │ row actions ⋮ │
└───────────────────────────────────────────────────────────────┘
Pagination: page size 25 (10/25/50/100)
(RTL يعكس الترتيب أفقياً)
```

| البند | القاعدة | المصدر |
|---|---|---|
| البحث | خادمي، على الحقول المسماة في مواصفة الكيان، escaping صحيح، debounce 300ms داخل Cubit، وآخر طلب يفوز | مواصفة الماركات §10 |
| فلتر الحالة | الكل / نشط / موقوف (كل جداول CAT-07 فيها `is_active`) | DATA_MODEL §8 |
| الفرز | افتراضي حسب `sort_order` ثم الاسم إن وُجد العمود، وإلا الاسم؛ التفاصيل في مواصفة الكيان | اقتراح |
| عدد النتائج | الإجمالي بعد البحث والفلتر (`Prefer: count=exact`)، لا عدد الصفحة | مواصفة الماركات §10 |
| الترقيم | `AppConfig`: الافتراضي 25، الخيارات 10/25/50/100 | قرار-75 |
| التفاعل | أي تغيير بحث/فلتر يعيد الصفحة الأولى؛ إزالة فلتر الحالة لا تمسح البحث؛ «مسح الكل» يعيد الافتراضي | مواصفة الماركات §10 |
| الهاتف | بطاقات عبر `cardBuilder` تعرض الهوية والحالة أولاً؛ الإجراءات في قائمة المزيد | مواصفة الماركات §11 |

## C5. الإجراءات وقاعدة الإيقاف والحذف

| الإجراء | الصلاحية | العملية | الضبط |
|---|---|---|---|
| إنشاء | `masterdata.manage` | `POST /rest/v1/<table>` | لا يُرسل `is_active` (الافتراضي true) |
| تعديل | `masterdata.manage` | `PATCH ?id=eq.<id>` | الحالة لا تُعدَّل من النموذج |
| إيقاف | `masterdata.manage` | `PATCH` بجسم `{"is_active": false}` فقط | تأكيد قبل الإيقاف |
| إعادة تفعيل | `masterdata.manage` | `PATCH` بجسم `{"is_active": true}` فقط | دون تأكيد |
| حذف | `masterdata.manage` | `DELETE ?id=eq.<id>` | تأكيد صريح باسم السجل؛ **لا يظهر** إن كان الاستخدام المعروف أكبر من صفر |

- **الأصل في السيناريوهات:** «تعطيل بدل حذف ما استُخدم» (S46 وS47 وS49 وS50 وS52).
- الإيقاف يخرج السجل من الاختيارات **الجديدة** ويُبقيه في السجلات القائمة (S46-AC2 وS52-AC1).
- فشل `DELETE` بـ 409 أو 23503: حوار «السجل مستخدم» مع «إيقاف بدلاً من الحذف».
- بعد حذف/إيقاف آخر سجل في الصفحة: الرجوع صفحة واحدة إن أمكن.
- لا إعادة محاولة تلقائية لكتابة فاشلة (`RetryInterceptor` يعيد `GET` فقط).
- لا إجراءات جماعية: لا يرد أي منها في S46–S53.
- منع تكرار الإرسال: حالة Processing تعطّل الزر وتمنع النقر المزدوج.

## C6. النماذج والتحقق

- الحوار على التابلت والمكتب. على الهاتف full-screen أو bottom sheet **إن وفّره Core**، وإلا يبقى الحوار مع توثيق القيد. لا مكوّن عام جديد لأجل شاشة واحدة.
- التحقق عبر `AppValidator` / `ValidationRule` فقط؛ لا validator موازياً. حدود الطول من أنواع الأعمدة في DATA_MODEL.
- التكرار (409 أو 23505): رسالة واحدة مترجمة؛ لا يُحلَّل نص الخادم للتمييز بين الحقول.
- لا يُعرض نص الخادم الخام أبداً: `ExceptionMapper → Failure.messageKey → AppKey` (قرار-76).
- لا `UnsavedChangesGuard` في هذه المرحلة (D-C5).
- كل نص عبر مفاتيح ar/en مسجّلة في `key_registry`؛ لا نصوص ثابتة؛ لا `SnackBar` خام (`FlashMessages`)؛ تجنّب اسم عضو enum يساوي `name` لتعارضه مع `Enum.name`.

## C8. Responsive وRTL وLight/Dark وCore

- نقاط الاختبار 360 / 600 / 900 / 1200 على عرض الحاوية (V1_SCOPE). ليست breakpoints جديدة؛ استخدم `ScreenEngine` و`context.ui.grid` ومكوّنات Core.
- RTL/LTR: `Directional`؛ النصوص الطويلة وslug وURL وcode تُعرض بمحاذاة LTR داخل الواجهة RTL.
- الثيم: `context.ui.theme.colors` و`semanticColors` فقط؛ لا `Theme.of(context).colorScheme` في كود الميزة الجديد.
- **لون من البيانات** (مثل `hex_code`) ليس توكن ثيم؛ يُعرض كما هو مع حد `outlineVariant` حتى لا يختفي اللون الفاتح على خلفية فاتحة.
- `AppDensity`: لا تُضبط صراحة.
- **مكوّنات Core المؤكدة في مواصفة الماركات:** `ListPageTemplate`, `FilterBar`, `AppDataTable`, `AppEmptyState`, `AppImage`, `InlineBanner`, `AppButton`, `AppIconButton`, `AppTextField`, `AppBadge`, `AppCard`, `AppMenu`, `ConfirmDialog`, `FlashMessages`, `PermissionGate`, `AppValidator`, `SearchableDropdown`, `AppSkeleton`, `AppBreadcrumb`.
- **غير مؤكدة (واردة كـ«ناقصة» في خريطة التنقل §12.3، تُفحص في الكود قبل أي اقتراح):** Tabs (C20) · TreeView (C22) · EditableGrid (C23) · ColorSwatch (C26) · DynamicFormRenderer (C43) · ChipSelect (C44). إن لم تغطِّ Core الحاجة يُسجَّل النقص ويُعرض قبل إنشاء توسعة.

## C9. API وخريطة الأخطاء

PostgREST على `/rest/v1/<table>` عبر `IApiClient` و endpoint feature-owned: `GET` مع `select` و`order` و`Range` و`Prefer: count=exact`؛ `POST` و`PATCH ?id=eq.` و`DELETE ?id=eq.`.

| الحالة | التحويل |
|---|---|
| 409 أو 23505 | قيمة مكررة (رسالة واحدة) |
| 23503 | مستخدم؛ حوار إيقاف بدلاً من الحذف |
| 401 | انتهاء الجلسة |
| 403 أو 42501 | لا صلاحية |
| انقطاع | مشكلة اتصال |
| غير ذلك | خطأ عام |

- لا `message.contains('23505')`؛ استخدم `code/details` من `ApiException` إن دعمها العقد، وإلا أضفها إضافياً فقط مع اختبار.
- لا migration ولا RPC ولا View ولا dependency جديدة.
- **عدد الاستخدام** (`<child>(count)`) يُضمَّن فقط عند تفعيل عمود ثانوي (D-C3)، وقيد FK هو الحَكَم النهائي دائماً.

## C10. الاختبارات (مشتركة)

- Model: `fromJson/toJson/toEntity`. Repository: query/body/mapping/errors بـ fake لـ `IApiClient`. Cubit: loading/success/empty/error وdebounce وآخر طلب يفوز وProcessing.
- Widget: 360/600/900/1200 × LTR/RTL × Light/Dark مع `tester.takeException()`.
- اختبارات المعمارية لا تُعطَّل: `no_magic_numbers_test` و`no_raw_ui_in_features_test` و`feature_imports_test`.
- لا golden tests. التحقق البصري اليدوي على Chrome (360 و1200، عربي/إنجليزي، فاتح/داكن) يبقى للمالك.
- التحقق على Supabase الفعلي (حساب manage وحساب read-only) منفصل عن اختبارات fake.
- لم يُشغَّل أي أمر Flutter في إعداد هذه المواصفات؛ لا نتائج مزعومة.
