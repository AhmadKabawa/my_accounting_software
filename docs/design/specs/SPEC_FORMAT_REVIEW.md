## 3. تدقيق الماركات والألوان مقابل التنفيذ

### 3.1 الماركات — تنفيذ موجود

المراجع الفعلية:
- `BrandsEndpoint`: `/rest/v1/brands`، والحقول المختارة تشمل id/name/slug/logo/description/is_active/updated_at، مع `products(count)`.
- `BrandsRemoteDataSourceImpl`: البحث على name وslug، فلتر is_active، وفرز خادمي.
- `BrandListQuery`: فرز name/status/id/updated_at؛ لا يوجد created_at في جدول brands.
- `brandsListConfig`: جدول/بطاقات/شبكة، إحصاءات، إنشاء/تعديل/حذف مشروط، تفعيل/إيقاف، تكرار وإجراءات جماعية.
- `BrandsRoutes` و`CatalogRoutes`: المساران الفعليان `/catalog/brands` و`/catalog`؛ `/catalog/master-data` alias يعيد إلى مركز الكتالوج، وليس إلى صفحة الماركات مباشرة.

حقول DB: name وslug إلزاميان بطول 150 وكلاهما فريد، logo بطول 500، description، is_active افتراضه true، وأعمدة المزامنة القياسية ومنها updated_at. RLS: القراءة true والكتابة masterdata.manage.

**فجوة مؤكدة:** BACKEND_REQUESTS B-01 يثبت أن سياسة Storage لرفع الشعار في `product-images` تتطلب `catalog.manage` بينما جدول brands يتطلب `masterdata.manage`. واجهة الماركات تحرس الإدارة بـ masterdata.manage، لكن رفع الشعار قد يُرفض للمستخدم الذي يملك هذه الصلاحية وحدها. لم أغيّر السياسة أو الكود؛ يلزم قرار Backend واختبار حساب محدود الصلاحية.

**ملاحظات لا يجوز إسقاطها:** لا يوجد created_at في brands؛ لا يُدّعى فرز «الأحدث إنشاءً» بناءً على هذا العمود. التطبيق يستعمل id كبديل تقريبي موثق في BrandListQuery. إحصاءات الماركات الحالية بطلبَي count وليست RPC واحدة. تنظيف ملف الشعار القديم عند الاستبدال/الحذف ما زال بنداً مفتوحاً في BACKEND_REQUESTS.

المراجع الفعلية:
- `ColorsEndpoint`: `/rest/v1/colors` ويختار id/name/code/hex_code/is_active/sort_order.
- `ColorsRemoteDataSourceImpl`: البحث على name وcode وhex_code؛ فلتر is_active؛ إنشاء وتعديل وحذف وتفعيل/إيقاف.
- `ColorListQuery`: الافتراضي sort_order تصاعدياً ثم name؛ الفرز المتاح order/name/code؛ حجم الصفحة 25.

- `ColorsRoutes`: المسار الفعلي `/catalog/colors`.

حقول DB: name 100 إلزامي، code 50 إلزامي وفريد، hex_code اختياري حتى 9 مع CHECK يقبل #RRGGBB أو #RRGGBBAA، is_active افتراضه true، sort_order افتراضه 0. RLS: القراءة true والكتابة masterdata.manage.

**انحرافات عن مواصفة CAT-07_colors.md القائمة:**
1. المواصفة تقول إن الحذف غير موجود، لكن الكود يوفّر حذفاً مفرداً وجماعياً.

3. المواصفة تقصر البحث على name/code، لكن الكود يبحث أيضاً في hex_code.
4. المواصفة لا تذكر أو لا تعتمد التكرار والحذف الجماعي، بينما تكوين القائمة يفعّلهما.
5. المواصفة تشترط عدم إظهار الحذف للون المستخدم. الكود لا يمرر شرط `canDelete` مثل الماركات ولا يعرض عدد الاستخدام؛ لذلك لا يثبت أن زر الحذف مخفي. قيد FK على product_color_components.color_id قد يرفض الحذف من الخادم عند الاستخدام، لكن ذلك ليس بديلاً عن إخفاء الإجراء المطلوب في الواجهة.
