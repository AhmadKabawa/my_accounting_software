# قرارات أمان الجلسة

قراران مقبولان لكنهما **موثقان عمداً** وليسا سهواً.

## 1) صلاحية الجلسة المخزَّنة

`AuthRepositoryImpl.getCurrentUser` يعيد المستخدم المخزَّن دون سؤال السيرفر، ولا يطرده عند فشل الشبكة (يطرده عند 401/403 فقط). النتيجة: حساب معطّل أو تغيّرت صلاحياته يبقى داخلاً حتى يفشل أول refresh.

- **المخاطرة:** في برنامج محاسبي بصلاحيات، تأخّر سحب الصلاحية.
- **المطلوب لاحقاً:** إعادة تحقق في الخلفية عند بدء التطبيق أو بمهلة صلاحية للنسخة المخزَّنة. لم تُنفَّذ بعد.

## 2) تسجيل الخروج بلا إنترنت

`logout()` يمسح الجلسة محلياً حتى لو فشل إلغاؤها على السيرفر، فيبقى الـ refresh token صالحاً هناك حتى انتهائه. السلوك مقصود: المستخدم يخرج دائماً. الفشل يُسجَّل بـ `Logger.warning` (نوع الاستثناء فقط).

## السجلات

لا يُعرض نص استثناء داخلي للمستخدم أبداً؛ الواجهة تعرض `messageKey` فقط. `RepositoryExecutor` يسجّل الأخطاء غير المتوقعة مع stack trace ولا يضع نصها في `Failure`. لا تُسجَّل توكنات ولا بيانات شخصية.
