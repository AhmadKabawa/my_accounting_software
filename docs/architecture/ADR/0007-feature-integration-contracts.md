# ADR-0007: تكامل الميزات دون تجاوز حدود ADR-0004

- الحالة: **مقترح**
- التاريخ: 2026-11-21

## السياق

تحتاج ميزات ERP أحياناً إلى إنشاء أو اختيار كيان مرتبط من سياق شاشة أخرى (مثلاً إنشاء لون أو اختيار لون من المنتج، أو عرض قواعد تسعير مرتبطة بماركة). يجب ألا يؤدي هذا إلى استيراد صفحات/Cubits/Data مباشرة بين الميزات، وهو ممنوع وفق ADR-0004.

## الخيارات

1. **تبادل عبر routes فقط:** مناسب للتنقل، لكنه محدود عند الحاجة إلى نتيجة/اختيار متبادل.
2. **عقد مشترك في Core (typed request/result أو capability contract):** يبقى Core مستقلاً عن الميزات؛ تستضيف الميزات تنفيذ العقد وتعيد نتيجة عبر route/state boundary. يحتاج تعريفاً ضيقاً ومبرراً للمستهلكين.
3. **Feature imports مباشرة:** أبسط مؤقتاً، لكنه يخالف ADR-0004 ويزيد coupling؛ غير مقبول دون استثناء ADR محدد.

## التوصية

الخيار 2 عند وجود تكامل فعلي متكرر، مع routes للتنقل، وعقد Core ضيق لا يتضمن تفاصيل Feature ولا يفرض منطق أعمال في Core. لا يُنشأ عقد عام مسبقاً لحالة واحدة دون مبرر، وتبقى خيارات الخيار 1 هي المفضلة للتنقل البسيط. لا يغيّر هذا المقترح ADR-0004 ولا يصرّح بأي استيراد Feature-to-Feature.

## الأثر

لا تنفيذ كود تابع لهذا القرار حتى اعتماده. توثّق حالات التكامل في integration-impact.md وتُراجع مع DATA_MODEL وBACKEND_REQUESTS.md.
