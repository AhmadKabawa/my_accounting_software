# ADR-0004: الاستيراد بين الميزات عبر ملف routes فقط

- **الحالة:** معتمد
- **التاريخ:** 2026-11-16
- **الجهة صاحبة القرار:** مالك المشروع (وافق في مراجعة ما قبل الإصدار الأول)
- **النطاق:** `lib/app/features/`

## السياق

كانت `ARCHITECTURE_RULES.md` تصف هذه القاعدة بأنها «مقترحة بانتظار موافقة المالك» وتمنع إنشاء ADR لها، بينما يفرضها فعلاً الاختبار `test/architecture/feature_imports_test.dart`، ويحوي قائمة `_knownDebt` بعدة استيرادات قديمة. الرقم ADR-0002 مستعمل لموضوع آخر (نمذجة الحالات).

## القرار

1. لا تستورد Feature من Feature أخرى إلا ملف routes الخاص بها: `features/<other>/presentation/routing/<other>_routes.dart`، وذلك للتنقل فقط.
2. لا يجوز استيراد صفحات ميزة أخرى ولا Cubits ولا data ولا مفاتيح نصوصها. المشترك يُنقل إلى Core أو إلى عقد Domain عام موثّق ومستقل عن Presentation وData.
3. أي استثناء يُسجَّل في ADR جديد قبل اعتماده.
4. الديون القديمة تبقى مسجلة في `_knownDebt` داخل الاختبار، **ويجوز أن تتقلص فقط**: مخالفة جديدة تفشل الاختبار، وكذلك بند لم يعد موجوداً (يُحذف).

## النتائج

- حدود الميزات قابلة للفحص آلياً داخل `flutter test`.
- الديون الحالية (مثل استيراد `profile` لـ `SessionCubit` و`auth_keys`) تُعالج بنقل العقد المشترك إلى Core عند أول مستهلك ثانٍ، ولا يُنشأ منها دين جديد.

## التحقق

الاختبار موجود في المستودع. لم يُشغَّل في جلسة كتابة هذا القرار (لا Flutter SDK)؛ يُشغَّل محلياً وتُوثَّق نتيجته وفق `ARCHITECTURE_RULES §9`.
