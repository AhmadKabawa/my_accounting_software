# ADR-0006: دورة حياة لقطة صلاحيات المستخدم (C47)

- **الحالة:** مقترح منفذ على فرع العمل للمراجعة؛ لا يُدمج قبل مراجعتك.
- **التاريخ:** 2026-11-17
- **المرجع:** قرار-68، `docs/backend/GET_MY_ACCESS.md`.

## السياق

تعيد `public.get_my_access()` هوية المستخدم وأدواره وصلاحياته ونطاقات الفروع والمستودعات ونقاط البيع. يجب ألا تبقى صلاحيات قديمة بعد انتهاء الجلسة أو فشل تحديثها. كما أن التخزين الدائم يضيف احتمال استعمال صلاحيات قديمة بعد تعديلها في قاعدة البيانات.

## القرار

1. **لا تخزين دائم للصلاحيات.** تُحفظ `AccessSnapshot` في ذاكرة التطبيق فقط، ولا تُكتب في Hive أو SharedPreferences أو أي تخزين محلي.
2. تُحمّل اللقطة بعد نجاح استعادة الجلسة أو تسجيل الدخول، ولا تصبح الصلاحيات فعّالة إلا بعد نجاح التحليل الكامل للرد.
3. عند فشل الطلب أو وجود حقل/نوع غير مطابق للعقد، تكون الحالة `failure` ولا يُسمح بأي صلاحية. يتاح `retry()` لإعادة الطلب.
4. تُمسح اللقطة فور تسجيل الخروج أو إبطال الجلسة أو فشل إثبات وجود مستخدم.
5. تغيير الفرع المقبول من قائمة الفروع المسموح بها يحدّث الفرع المحدد ثم يعيد طلب اللقطة قبل اعتبار النطاق جاهزاً. الفرع الوحيد القابل للعرض يُحدد تلقائياً؛ مع عدة فروع لا يُفترض اختيار فرع.
6. لا تمنح `is_super_admin` صلاحيات محلية مستقلة؛ قائمة `permissions` المعادة من الخادم هي التي تُستخدم في فحوص الواجهة. لا تُعد الواجهة بديلاً عن RLS.

## النتائج

- لا توجد نافذة صلاحيات مخزنة بعد إغلاق التطبيق.
- كل تحميل جديد يحتاج اتصالاً ناجحاً؛ الفشل يقفل الوظائف حتى إعادة المحاولة.
- أي كود صلاحية غير معروف للتطبيق يُتجاهل إلى أن يضاف صراحةً إلى سجل الصلاحيات المعروف.
- إعادة تحميل الفرع قد تفشل؛ عندها تبقى الوظائف مقفلة ولا يُستخدم snapshot سابق.
